# Espejo — 얼굴 스캔 피부진단

Lococo × Oki Doki Labs 행사(2026-09-26~27, 마드리드) 현장용. 아이패드에서 얼굴을 촬영해
**광학 측정 + Baumann 문진**으로 피부 진단 결과지를 만든다.
스페인어 / 영어 / 한국어 전환 — 우상단 `ES · EN · KO` 토글.

**라이브**: https://lococo-skin-type-analysis.isty-stock.workers.dev
**보정 모드**: 위 주소 + `#calibrar` (관람객에게는 안 보임)

**분석은** 전부 클라이언트 사이드다. 이미지와 진단 결과는 브라우저 메모리에서만 처리되고
어디에도 저장되지 않는다. **유일한 네트워크 호출은 이메일 수집**(`POST /api/lead`)이며,
거기에는 연락처만 담긴다 — 진단 결과는 절대 함께 보내지 말 것. 피부 지표는 GDPR상
건강 데이터에 해당해서 전시 부스가 감당할 수 없는 법적 요건이 붙는다.

| `build.mjs` | 배포용 완전 HTML 문서 생성 → `dist/` |
| `wrangler.jsonc` | Cloudflare 배포 설정 |

### `index.html`이 반쪽짜리인 이유

Artifact로도 게시할 수 있게 하려고 `<!doctype>`, `<html>`, `<head>`를 뺐다. Artifact 컨테이너가
그걸 넣어준다. **자체 배포에는 컨테이너가 없으므로** `build.mjs`가 charset·viewport·favicon을
붙인 완전 문서를 만든다. viewport 메타가 없으면 모바일이 980px로 렌더링하고 스페인어
악센트가 깨진다. 소스는 하나, 목적지는 둘.

## 남은 과제 — 실제 얼굴 보정

`engine.js`의 `BANDAS`(물리값 → 0~100 지수 환산 구간)는 **합성 이미지로만 맞춘 잠정값**이다.
물리 측정 자체와 존 간 비교는 지금도 유효하지만, "23이 정상인가 높은가"를 말하는 기준선은
실제 얼굴 근거가 없다.

**절차**

1. 라이브 URL + `#calibrar` 로 접속
2. 행사에 쓸 **같은 아이패드, 같은 조명**으로 얼굴 15~20장 촬영
3. p10/p90이 자동 계산되고 `BANDAS` 블록이 생성됨
4. 그 블록을 `engine.js`의 `var BANDAS = {...}` 자리에 붙여넣고 재배포

**주의** — 비슷한 얼굴만 모으면 밴드가 좁아져서 지수가 0에서 100으로 튄다. 피부톤·연령·
피부 상태를 일부러 섞을 것. 도구가 p10~p90 폭이 중앙값의 15% 미만이면
`dispersión insuficiente`로 경고하고 그 밴드는 적용하지 않는다.

숫자만 브라우저 localStorage에 저장된다. 이미지는 저장하지 않는다.
`#calibrar` 화면 맨 아래에서 JSON 백업을 뜰 수 있다.

## 이메일 수집과 결과지 발송

**⚠️ 발송은 아직 꺼져 있다.** `RESEND_API_KEY` 시크릿이 없으면 `/api/capacidad`가
`{envio:false}`를 돌려주고, 화면은 "결과지를 보내드릴게요"라고 **말하지 않는다**. 보내지도
않을 걸 보내준다고 하면 방문자를 속이는 것이고, GDPR상으로는 수집 목적을 거짓으로
선언하는 것이 된다. 키를 넣는 순간 문구·필수 동의·자동 발송이 한꺼번에 켜진다.

```bash
npx wrangler secret put RESEND_API_KEY     # Resend API 키
npx wrangler secret put REMITENTE          # 예: "Espejo <espejo@lococo.beauty>"
```

Resend에서 `lococo.beauty` 도메인 인증(SPF/DKIM)을 먼저 끝내야 한다. 인증 없이는 메일이
스팸으로 가거나 반송된다.

- 소개 화면 다음, 촬영 전에 물어본다. **이메일은 필수다** — 결과지를 보내려면 주소가
  있어야 하므로 서비스 제공에 필요한 정보다. 마케팅 동의는 **별도 체크박스이고 여전히
  선택**이다. 둘을 묶으면 동의 끼워팔기가 된다.
- 결과지 발송에는 **별도의 명시적 동의**를 받는다. 결과지에는 피부 상태 정보가 들어가고
  이는 GDPR 9조 건강 데이터라, 마케팅 동의로 갈음할 수 없다.
- **결과지는 저장하지 않는다.** `/api/informe`는 메일 제공자로 중계만 하고 사본을 남기지
  않는다 — D1에도, 로그에도, KV에도. D1에 들어가는 건 연락처뿐이다.
- 동의 체크 없이는 저장·발송하지 않는다. API를 직접 호출해도 `400`으로 거부한다.
- 저장 위치: Cloudflare D1 `espejo-leads`, **weur(서유럽) 리전**. 마드리드 행사라
  EU 역내에 두는 편이 국제 이전 논란을 피한다.
- 저장 항목: 이메일, 언어, 동의 플래그, 세션 ID, 시각. **진단 결과는 저장하지 않는다.**

```bash
# 수집된 목록 보기
npx wrangler d1 execute espejo-leads --remote \
  --command "SELECT email, idioma, creado FROM leads ORDER BY id DESC;"
```

> ⚠️ **행사 전 반드시 확인**: 동의 문구에 수신거부 주소로 `hola@lococo.beauty` 가 적혀
> 있다. 실제로 받는 주소인지 확인하고, 아니면 `i18n.js`의 `cor.consent` 3개 언어를
> 모두 고칠 것. 수신거부 경로가 실제로 동작하지 않으면 GDPR 위반이다.

## 문진 — 5문항

`perfil.js`의 `TODAS`에 13문항이 그대로 있고, 현장에서는 `ACTIVAS = [0, 3, 7, 9, 12]` 다섯 개만 쓴다
(Baumann 4축 각 1문항 + 수분). 빠진 문항은 카메라가 이미 재는 것(유분·붉은기·색소)을 다시 묻던 것들이다.
**수분 문항은 빼지 말 것** — 카메라로는 원리상 못 잰다. 13문항으로 되돌리려면 `ACTIVAS`만 고치면 된다.

## 확대 분석 (결과지 03)

코·오른쪽 볼·이마를 **측정에 쓴 같은 사진**에서 96px(≈25 mm) 잘라 3배로 보여준다. 두 번째 촬영은 없다.
- 청록 원: 결 대역(r1–r4)의 국소 최저점 중 −1.8σ 아래. 정반사(> 0.42)와 그 3px 이내, 병변 안쪽은 제외.
  **광학 지표이지 임상 모공 개수가 아니다** — 화면 주석에도 그렇게 적혀 있다.
- 빨간 원: 5단계에서 검출한 국소 병변, 실제 크기.
- 5 mm 눈금은 타일 폭에 대한 비율로 그려서 화면 크기와 무관하게 맞는다.
- 사진은 메모리에서만 그리고 메일 결과지에는 넣지 않는다.

## 제품 추천

`catalogo.js`가 실리콘투 1차 발주 리스트에서 뽑은 97개 제품을 담고 있다. 진단 결과에서
6개 목표(모공·트러블·진정·수분·미백·탄력)에 가중치를 매기고, 5개 루틴 슬롯에 배분한다.

- **결정적이다.** 같은 피부는 항상 같은 루틴을 받는다. 같은 피부를 두 번 읽었는데 추천이
  바뀌면 그건 추천이 아니라 추첨이다.
- 이미 커버된 목표는 다음 슬롯에서 가중치가 0.4배로 내려간다. 이게 없으면 지배적인 목표
  하나가 5단계를 전부 먹어서 같은 태그가 다섯 번 반복된다.
- 재고가 바뀌면 `catalogo.js`의 `PRODUCTOS` 배열만 교체하면 된다.

## 설계상 건드리면 안 되는 것

측정의 신뢰성이 여기 달려 있다. 바꾸려면 이유를 알고 바꿀 것.

- **촬영 5조건 게이팅** — 노출·좌우 광량·초점·프레이밍·흔들림. 이게 없으면 같은 피부를
  두 번 찍어도 값이 달라져서 측정이 무의미해진다.
- **영상 주위 흰 링** — 아이패드 화면이 필라이트다. 시안색 빛이 얼굴에 닿으면 G채널이
  올라가 홍반지수(`log(R/G)`)가 실제보다 낮게 나온다. 링은 반드시 중성 백색.
- **3:4 종횡비** — 존 좌표계가 이 비율 위에 정의돼 있다. 바꾸면 측정 부위가 전부 어긋난다.
- **"수분·탄력은 측정 불가" 표기** — 카메라로는 원리상 안 된다. 문진으로 처리하고 결과지에
  구분 표기한다. 이걸 흐리면 아는 사람에게 바로 들통난다.
- **분석 경로에 네트워크 호출 0건** — 이메일 수집(`/api/lead`)이 유일한 예외이며 연락처만
  보낸다. 진단 결과를 여기에 실어 보내는 순간 GDPR상 건강 데이터 처리가 되고, 결과지의
  프라이버시 문구가 거짓이 된다.
