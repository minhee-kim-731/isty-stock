# ISTY 재고 데스크

실리콘투에서 들여온 재고와, 매일 들어오는 주문의 출고를 3PL 실장님과 함께 보는 대시보드.
Cloudflare Workers + D1 위에서 돕니다. **무료 요금제로 운영됩니다.**

## 주소

**https://isty-stock.isty-stock.workers.dev**

접속 코드는 **`ACCESS.local.md`** 에 있습니다 (저장소에는 올라가지 않는 파일입니다).

실장님께는 위 주소와 **창고 코드만** 주세요.
데이터베이스는 유럽(WEUR, 런던)에 있습니다 — 실장님 쪽 응답을 우선했습니다.

## 되돌리기 — 잘못했을 때

이 앱에서 제일 중요하게 만든 부분입니다. 되돌리는 수단이 네 겹으로 있습니다.

**1. 주문을 잘못 등록했거나, 준비 완료를 잘못 눌렀을 때**
주문 탭에서 `취소` 를 누릅니다. 아직 안 나간 주문이면 잡아둔 재고가 풀리고,
**이미 준비 완료한 주문이면 재고가 창고로 되돌아옵니다.** 원장에는 `반환` 으로 남습니다.

**2. 입고 수량을 잘못 넣었을 때**
입고 탭의 이력에서 `되돌리기` 를 누릅니다. 그 입고로 더해진 수량이 재고에서 다시 빠집니다.
이미 팔려나가서 뺄 재고가 없으면 어떤 제품이 몇 개 모자란지 알려주며 거절합니다
(그때는 재고 조정으로 맞추세요).

**3. 재고 숫자가 이력과 안 맞을 때**
현황 탭 아래 `재고 재동기화`. 재고 숫자를 이력(입고·출고·조정·반환)의 합계로 다시 계산합니다.
무엇이 얼마에서 얼마로 바뀌었는지 알려줍니다.

**4. 그보다 크게 잘못됐을 때 — 데이터베이스 통째로 되감기**
D1은 **지난 30일 중 아무 시점으로나** 되돌릴 수 있습니다. 항상 켜져 있고 추가 비용이 없습니다.

```bash
# 지금으로부터 2시간 전으로 되돌리기
npx wrangler d1 time-travel restore isty --timestamp="$(date -u -v-2H +%Y-%m-%dT%H:%M:%SZ)"

# 되돌리기 전에 그 시점이 어떤 상태인지 먼저 확인
npx wrangler d1 time-travel info isty --timestamp="..."
```

**그리고 백업.** 현황 탭의 `백업 내려받기` 를 누르면 지금 시점의 제품·주문·입고·재고 이력
전부가 JSON 파일 하나로 떨어집니다. 큰 작업(대량 입고 등) 전에 한 번 받아두면 마음이 편합니다.

## 실행 (내 맥에서 개발용)

```bash
npm install
npm run db:local     # 로컬 데이터베이스에 스키마 적용 (처음 한 번)
npm run dev          # http://localhost:8787
```

로컬 접속 코드는 `.dev.vars` 에 있습니다. 이 파일은 git에 올라가지 않습니다.
로컬 데이터베이스는 `.wrangler/` 안에 있고, 배포된 것과 완전히 별개입니다.

## 배포 (Cloudflare)

### 처음 한 번만 (이미 끝났습니다 — 기록용)

1. [dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up) 에서 계정을 만듭니다. **카드 필요 없습니다.**
2. 로그인합니다. 브라우저가 열립니다.

   ```bash
   npx wrangler login
   ```

3. 데이터베이스를 만들고, 출력된 `database_id` 를 `wrangler.jsonc` 의 `PLACEHOLDER...` 자리에 붙여넣습니다.

   ```bash
   npx wrangler d1 create isty
   ```

4. 스키마를 넣고, 접속 코드를 비밀값으로 등록합니다.

   ```bash
   npm run db:remote
   npx wrangler secret put ISTY_BRAND_CODE       # 브랜드 코드 입력
   npx wrangler secret put ISTY_WAREHOUSE_CODE   # 창고 코드 입력
   ```

5. 올립니다.

   ```bash
   npm run deploy
   ```

`https://isty-stock.<계정이름>.workers.dev` 주소가 나옵니다. 실장님께는 이 주소와 창고 코드를 주세요.
제품 데이터(1차 발주분 39품목 314개)는 처음 로그인할 때 자동으로 들어갑니다.

### 그다음부터

코드를 고쳤으면 이거 한 줄이면 됩니다. 몇 초 걸립니다.

```bash
npm run deploy
```

## 접속 코드

브랜드용과 창고용이 따로 있고, 할 수 있는 일이 다릅니다.

| | 브랜드 (민희) | 창고 (실장님) |
|---|---|---|
| 주문 등록·취소 | O | X |
| 입고 등록·되돌리기 | O | X |
| 제품 등록·보관 | O | X |
| 백업, 재고 재동기화 | O | X |
| 주문 수락, 포장 완료 | O | O |
| 주문 취소 | O | 포장 완료한 건만 |
| **재고 조정 (사유 필수)** | O | **O** |
| 재고 조회, 재고 이력 보기 | O | O |
| 제품 메모 (공유) | — | O |
| 제품 메모 (본인 전용) | O | — |
| 개수 점검 기록 | O | O |
| 처리 내역 (날짜별) | — | O |

실장님 계정에는 브랜드 화면으로 넘어가는 길이 아예 없습니다. 반대로 민희님은 상단바의
`실장님 화면 보기` 로 실장님이 보는 화면을 미리 볼 수 있고, 그때는 본문 위에 점선 띠가 떠서
미리보기 중임을 알려줍니다 (실장님께는 이 띠가 보이지 않습니다).

바꾸려면 아래를 실행하고 새 코드를 입력하면 됩니다. 재배포는 필요 없고 즉시 적용됩니다.

```bash
npx wrangler secret put ISTY_WAREHOUSE_CODE
```

### 로그인 시도 제한

접속 코드가 짧기 때문에 이게 실질적인 방어선입니다.
**같은 IP에서 8번 틀리면 10분간 잠깁니다.** 잠긴 동안에는 맞는 코드도 받지 않습니다.

실장님이 코드를 잊어서 잠겼다면 이렇게 바로 풀 수 있습니다.

```bash
npx wrangler d1 execute isty --remote --command "DELETE FROM login_attempts" -y
```

코드를 더 길게 바꾸면 이 방어선에 덜 기대게 됩니다. 지금처럼 6자리를 쓰신다면
주소를 아무 데나 공유하지 마세요.

접속 코드는 `ACCESS.local.md` 에만 있고 이 파일은 `.gitignore` 에 들어 있어
저장소에 올려도 코드는 따라가지 않습니다.

## 일하는 순서

**민희님** — 주문 탭에서 주문을 등록합니다. 고객명, 배송지, **택배회사·송장번호**,
실장님께 남길 메모, 담을 제품. 송장번호를 아직 모르면 비워두세요 — 실장님이 포장할 때 넣을 수 있습니다.

**실장님** — 탭이 셋입니다. **출고 작업**(할 일), **처리 내역**(끝낸 일), **재고 조회**.
출고 작업 탭에 주문이 한 줄씩 뜨고, 줄에는 **주문자 이름과 품목 개수만** 보입니다.

1. `주문 수락` 을 눌러 접수했음을 알립니다 (상태가 *포장 중* 으로 바뀝니다).
   목록에서도, 주문 상세에서도 누를 수 있습니다.
2. 줄을 누르면 **주문 상세**로 들어갑니다. 민희님이 남긴 메모와 담을 제품 목록이 있고,
   **택배회사와 송장번호가 큼직하게** 표시됩니다 (송장번호 복사 버튼도 있습니다).
   민희님이 미리 넣어둔 값은 포장 완료 칸에 채워져 나오고, 실장님이 비우지 않으면 그대로 유지됩니다.
3. 담을 때마다 제품별 체크박스를 누릅니다. 바코드가 함께 보입니다.
   **수락 전에는 체크박스가 잠겨 있습니다** — 화면에서만이 아니라 서버에서도 막습니다.
   전부 담기 전에는 포장 완료도 되지 않습니다.
4. 전부 담으면 맨 밑 `포장 완료` 가 켜집니다. 택배사·송장번호는 선택입니다.
   **누르면 재고에서 빠지고 민희님께 알림이 갑니다.**
5. 처리한 주문은 **처리 내역** 탭에 날짜별로 쌓입니다. 그날 몇 건을 처리했는지,
   각 주문이 몇 시에 나갔고 송장번호가 뭐였는지 여기서 봅니다.
6. 잘못 눌렀으면 그 주문을 다시 열어 `주문 취소` 를 누릅니다. 뺐던 재고가 창고로 돌아오고,
   이것도 민희님께 알림이 갑니다. 실장님은 **포장 완료한 주문만** 취소할 수 있습니다
   (아직 포장 전인 주문을 무르는 건 민희님 몫입니다).

### 제품 메모 — 누가 쓰느냐에 따라 보이는 범위가 다릅니다

| 쓴 사람 | 보이는 사람 | 표시 |
|---|---|---|
| 실장님 | 민희님 + 실장님 | `실장님` 태그 |
| 민희님 | **민희님만** | `나만` 태그 |

메모 칸을 누르면 **내가 쓸 수 있는 메모**가 열립니다. 민희님이 열면 본인 전용 메모가,
실장님이 열면 공유 메모가 열립니다. 민희님 화면에서는 실장님이 남긴 메모도 창 안에
읽기 전용으로 함께 보입니다.

민희님 전용 메모는 서버에서 아예 걸러내므로 창고 화면으로는 내려가지 않습니다.
재고를 조정할 때는 실장님 메모가 조정 창에 함께 뜹니다.

### 개수 점검

재고 화면 오른쪽 위의 `개수 점검` 버튼을 누르면 창이 뜹니다.

- **어느 발주분인가요** — 1차, 2차… 발주 목록에서 고릅니다 (최신 발주가 기본)
- **누가 점검했나요** — Lococo 또는 ISTY
- **메모** — 실사 결과를 자유롭게 적습니다

기록은 재고 화면 아래 **개수 점검 기록** 표에 쌓이고, **민희님과 실장님 화면에 똑같이** 보입니다.

### 재고 상태 표시

부족·품절 같은 상태 배지는 재고 표에서 뺐습니다 (SKU당 수량이 적어 거의 항상 뜨는 탓).
현황 화면의 **재고 부족 · 품절** 카드는 그대로 두었습니다.

조정할 때 적는 **사유**와는 다릅니다. 사유는 "이번에 왜 고쳤는지"를 이력에 한 줄 남기는 것이고,
메모는 "이 제품에 대해 계속 알아둘 것"을 붙여두는 쪽지입니다.
(예: 박스 찌그러짐 / 유통기한 2027-03 / 다음 발주 때 수량 늘리기)

### 민희님께 알림이 가는 경우

실장님이 이 넷 중 하나를 하면 민희님 현황 화면 맨 위에 알림 카드가 뜨고 탭에 개수 배지가 붙습니다.

- 주문 **포장 완료**
- 포장 완료한 주문 **취소**
- **재고 조정**
- **제품 메모** 작성·수정
- **개수 점검** 기록

`확인했어요` 를 누르면 사라집니다. 민희님 본인이 한 일은 알림에 뜨지 않습니다.

### 실장님이 재고를 고칠 때

재고 조회 탭의 −/+ 로 실물과 숫자를 맞출 수 있습니다. **왜 고쳤는지 한 줄 적어야 저장됩니다.**
조정 내역은 재고 원장에도 사유와 함께 남으므로, 나중에 `이력` 으로 언제든 다시 볼 수 있습니다.

## 주문 상태

| 상태 | 뜻 |
|---|---|
| **포장 대기중** | 민희님이 등록했고, 실장님이 아직 수락하지 않음 |
| **포장 중** | 실장님이 수락함. 제품을 담는 중 |
| **포장 완료** | 다 담고 마감. 이때 재고가 빠짐 |
| **취소** | 취소됨. 포장 완료 후 취소하면 재고가 돌아옴 |

민희님의 **주문 탭** 위쪽에 상태별 칩이 개수와 함께 있습니다 (전체 / 포장 대기중 / 포장 중 /
포장 완료 / 취소). 눌러서 그 상태만 걸러 볼 수 있고, 기본은 전체라 **끝난 주문도 계속 보입니다.**
포장 완료된 주문은 상태 밑에 완료 시각도 함께 표시됩니다.

알림 카드는 `확인했어요` 를 누르면 사라지지만, 이 목록은 사라지지 않습니다.
"실장님이 처리했는지" 는 언제든 여기서 확인하세요.

## 주문 감추기 (지우지 않고)

테스트로 넣은 주문처럼 화면에서만 치우고 싶을 때 씁니다. `orders.hidden = 1` 로 두면
목록·통계·출고대기 계산에서 모두 빠지지만 서버에는 기록이 그대로 남습니다.

주문번호는 UNIQUE 라서, 같은 번호를 다시 쓰려면 감출 때 번호도 함께 바꿔줘야 합니다.

```bash
# 지금 보이는 주문 전부를 감추고, 번호 뒤에 (테스트)를 붙여 번호를 풀어준다
npx wrangler d1 execute isty --remote -y --command \
  "UPDATE orders SET hidden = 1, order_no = order_no || ' (테스트)' WHERE hidden = 0"

# 다시 보이게
npx wrangler d1 execute isty --remote -y --command "UPDATE orders SET hidden = 0 WHERE id = 6"
```

감춘 뒤에는 `meta.version` 을 올려야 열려 있는 화면이 갱신됩니다
(위 명령 뒤에 `INSERT INTO meta (key,value) VALUES ('version','1') ON CONFLICT(key) DO UPDATE SET value = CAST(CAST(meta.value AS INTEGER) + 1 AS TEXT)`).

**주의:** 이미 포장 완료된 주문을 감추면 그 출고분 재고는 되돌아오지 않습니다
(원장에 출고 기록이 남아 있으므로). 재고까지 되돌리려면 감추기 전에 `주문 취소` 를 먼저 하세요.

## 재고가 움직이는 규칙

- **현재고** — 창고에 실제로 있는 수량. 발송이 끝나야 줄어듭니다.
- **출고대기** — 아직 안 나간 주문이 잡아둔 수량.
- **가용** — 현재고 − 출고대기. 지금 더 팔 수 있는 수량.

모든 변동은 `stock_moves` 원장에 남습니다. 입고 / 출고 / 조정 / 반환 / 입고취소 다섯 가지이고,
누가 언제 어떤 주문 때문에 움직였는지가 함께 기록됩니다. 재고 화면의 `이력` 링크로 볼 수 있습니다.

D1에는 여러 문장을 묶는 대화형 트랜잭션이 없습니다. 그래서 재고를 건드리는 쓰기는 전부
**조건을 SQL 안에 넣어** 두었습니다. 실장님이 발송 버튼을 두 번 눌러도, 두 화면에서 동시에 눌러도
재고는 한 번만 빠집니다.
